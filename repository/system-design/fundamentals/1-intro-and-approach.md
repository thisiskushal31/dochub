# Introduction to System Design

## What is system design?

System design is the process of defining the **elements** of a system, their **interactions**, and **relationships** to satisfy a set of requirements.

- Take a problem statement → break it into smaller components → design each to work together.
- Typically: analyze current system, plan the new system, test the design. **Iterative**: multiple rounds of design, testing, refinement.
- In software: high-level design of a system—architecture and components. Also a common **interview** topic: design a system for a given problem, discuss trade-offs and alternatives.

---

## How to approach system design

| Step | Action |
|------|--------|
| **Understand the problem** | Gather requirements; identify users, needs, constraints. |
| **Define scope** | What the system will and will not do. |
| **Research existing systems** | Learn from similar systems; reuse what works. |
| **High-level design** | Main components and how they interact (diagram or flowchart). |
| **Refine** | Iterate on details until the design meets requirements. |
| **Document** | Write it down for reference and maintenance. |
| **Monitor and improve** | Design is ongoing; adapt to changing requirements. |

**Use case:** Use this sequence in interviews and when starting any new system or feature.
