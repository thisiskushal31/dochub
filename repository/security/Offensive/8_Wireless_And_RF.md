# Wireless and RF (overview)

[← Offensive](./README.md)

Wireless testing is its **own** legal minefield. Practice only on **your** AP / RF lab gear. Do not attack café or neighbor Wi-Fi.

## Literacy

| Topic | Point |
|-------|-------|
| Wi-Fi auth families | Open / PSK / enterprise (802.1X) — know which you are allowed to test |
| Evil twin / rogue AP | Social + RF; detect with wireless IDS where relevant |
| Bluetooth / IoT RF | Separate kit and laws; often out of web AppSec scope |
| Tools | Aircrack-ng, Bettercap — [Tooling Offensive](https://github.com/thisiskushal31/Tooling-and-Frameworks-Deep-Dive/tree/main/Security/Offensive) |

## Program note

Many product teams never need deep RF. If wireless is in scope for a job role, add dedicated lab time; otherwise treat this file as **awareness** and focus on web/cloud/identity tracks.
