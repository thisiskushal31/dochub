# 06 — Sync policies, waves, Projects, and RBAC

[← Previous](./05_Manifest_Sources_Tracking_And_Immutability.md) · [Argo CD](./README.md) · [Next: ApplicationSets →](./07_ApplicationSets_App_Of_Apps_And_Scale.md)

## 1. Concepts

### Automated vs manual sync

| Mode | Behavior | Common use |
|------|----------|------------|
| **Manual** | OutOfSync until a human (or automation) syncs | Production, regulated windows |
| **Automated** | New Git/OCI desired state triggers apply | DEV / staging when Git is trusted |

Automated sync lets CI avoid calling the Argo API for every deploy: **commit is the deploy signal**.

Example policy fragment:

```yaml
spec:
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    syncOptions:
      - CreateNamespace=true
```

### Prune

By default, automated sync **does not delete** resources that disappeared from Git (safety). Enabling **prune** makes deletions in Git become deletions in the cluster. Know the blast radius before turning it on for prod.

**allowEmpty** (when prune is on) permits an Application to sync to *zero* resources. Off by default so a bad empty path does not wipe an environment.

### Self-heal

Without self-heal, kubectl drift leaves the app OutOfSync until someone syncs. With self-heal, Argo CD re-applies Git when live drifts. That is powerful and political: it encodes “Git wins.” Pair with culture that forbids UI-only prod edits — or self-heal will undo “heroic” hotfixes (which should have been Git commits anyway).

### Sync windows

Define times when syncs are allowed or blocked (maintenance freezes, business hours only). Useful for shared prod change control without abandoning GitOps.

### Sync waves and hooks

Annotate resources to run in phases:

| Phase | When |
|-------|------|
| **PreSync** | Before main resources |
| **Sync** | With main apply |
| **PostSync** | After resources healthy |
| **SyncFail** | After a failed sync (cleanup) |
| **PreDelete / PostDelete** | Application deletion lifecycle |

Typical uses: PreSync migration Job; PostSync smoke Job. Failed PreSync aborts the sync. This is **ordering**, not traffic shifting — use [Argo Rollouts](../Argo_Rollouts/README.md) for canaries.

Hook delete policies control whether Jobs stick around after success/failure.

### Projects in practice

Create a Project per team or per sensitivity tier. Explicitly list:

- `sourceRepos` (and optionally deny patterns)  
- `destinations` (cluster + namespace pairs)  
- resource allow/deny lists  

Then put Applications in that Project — not in wide-open `default`.

The **`default` Project** starts permitting everything. Safe for a five-minute demo. Dangerous as the long-term home for prod Applications. Tighten or empty `default` once real Projects exist so nothing silently lands there.

### RBAC and SSO

Map IdP groups (OIDC/OAuth/LDAP/SAML via Dex or external OIDC) to Argo CD roles: who can sync, who can create apps, who is read-only. Local `admin` is for bootstrap. CI uses **project role tokens**, local accounts with `apiKey`, or OIDC token exchange — not a shared human password ([08](./08_Secrets_CI_Integration_And_Operations.md)).

## 2. Advanced concepts

### ApplicationSet-managed sync policy

Child Applications generated by ApplicationSets may **reset** manual tweaks to `syncPolicy` on reconcile. Change policy on the ApplicationSet template / modification controls, not only by editing the child in the UI.

### Retry and backoff

Transient API errors happen. Configure sync retry so a blip does not leave you stuck OutOfSync until Monday.

### Sync options worth knowing

Examples (names evolve — confirm in current docs): create namespace, respect ignore differences, skip dry-run on some resources, apply out of order when waves need it. Each option exists because someone hit a real Kubernetes apply constraint.

### Orphaned resources

Resources in the namespace that Argo CD does not manage can be reported. Useful for cleaning “someone applied this by hand” leftovers — careful in shared namespaces.

### Selective sync and hooks

Selective sync can skip hooks. Do not use selective sync as your normal prod path if hooks encode safety checks.

### Compare and diff strategies

Large apps need sensible diffing. Know that CRDs and server-side fields can create noisy diffs until ignore rules or health/customizations catch up.

## 3. Applications and use cases

| Environment | Typical policy posture |
|-------------|------------------------|
| Shared DEV | Auto-sync + prune + self-heal; loose but not `*` destinations for other teams’ prod |
| Staging | Auto-sync; self-heal on; mirrors prod shape |
| Production | Manual sync or sync windows; prune on but reviewed; self-heal optional per risk culture; strict Project |

| Tenancy need | Mechanism |
|--------------|-----------|
| Team A cannot deploy to team B namespace | Project destinations |
| Contractors read-only | SSO group → role without sync |
| Pipeline can sync one app | Project role token scoped tightly |
| Forbid app teams creating ClusterRoles | Project resource deny |

### Policy anti-patterns

- Auto-sync + prune + allowEmpty on prod with a single mistaken empty commit  
- Everyone in `default` Project forever  
- Self-heal off *and* no process — silent permanent drift  
- Sync hooks that run unboundedly expensive suites (belong in CI verify — [5](../5_Verify_Rollback_And_Synthetic_Tests.md))
