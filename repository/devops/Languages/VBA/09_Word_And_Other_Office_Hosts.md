# Word and other Office hosts

[← Back to VBA](./README.md)

## What this chapter covers

**Word** object-model literacy (`Application`, `Documents`, `Range`, `Selection`) plus **doors**—not full courses—for Outlook, PowerPoint, and Access. A short **cross-app Automation** sketch ties back to chapter **07**. Document open events point at chapter **12**. Default: **Microsoft 365 Apps VBA on Windows**.

You leave able to read Word macros without drowning in the entire OM, know what each sibling host is *for*, and review cross-app automation as an intentional systems choice—not a recorder accident.

---

## 1. Concepts

### 1. Word’s hierarchy (mental model)

```
Application
  └── Documents
        └── Document
              └── Range / Selection / Paragraphs / Tables / …
```

Word is **document-centric**. Excel thinks in grids; Word thinks in continuous content with ranges that have start/end positions. Staff macros usually: open or reference a `Document` → get a `Range` → insert, format, or export.

### 2. `Documents` and `Document`

```vb
Dim doc As Document
Set doc = ThisDocument          ' the doc hosting the VBA (Word)
' Set doc = Documents.Open(path)  ' when explicitly opening another file
```

| Handle | Meaning |
|--------|---------|
| `ThisDocument` | Project document that contains the code (ThisDocument class module) |
| `ActiveDocument` | Whatever document is active—fragile across windows |
| `Documents.Open` / `.Add` / `.Close` | Lifecycle |

Prefer `ThisDocument` for template/doc logic that ships with the file. Prefer explicit `Documents("name")` or stored references when multiple docs are open.

### 3. `Range` vs `Selection`

| Object | Role |
|--------|------|
| **`Range`** | A span of the document (positions, text, formatting)—works without UI focus |
| **`Selection`** | What the user (or macro) has selected—UI-coupled |

Same lesson as Excel’s Select avoidance (chapter **08**): prefer `Range` for automation. Use `Selection` only when the product requirement is “act on what the user highlighted.”

```vb
Dim rng As Range
Set rng = doc.Range(0, 0)   ' insertion point at start — literacy shape
rng.InsertAfter "Hello"
```

Exact positioning APIs are deep; literacy is: ranges are the unit of work, Selection is optional.

### 4. Story literacy (enough to not panic)

Word content lives in **stories** (main text, headers, footers, comments, …). Macros that only touch `ActiveDocument.Content` miss headers. When reviewing mail-merge or letterhead tools, ask which stories are in scope. Full story enumeration is product depth—flag as a door, do not pretend this chapter covers it.

### 5. Find/replace and fields (door)

Staff letter and contract macros often lean on `Find` / `Replacement` or document **fields** (merge fields, date fields). Literacy: these are Range-scoped operations with options (wildcards, formatting). Prefer explicit bookmarks or content controls when the document is a maintained template—magic whole-document replace is brittle and easy to over-match. Deep Find API mastery is Word product work; reviewers should demand sample docs in the test plan.

### 6. Other Office hosts — doors only

| Host | What VBA is typically *for* | Not this chapter |
|------|------------------------------|------------------|
| **Outlook** | Mail items, folders, appointments; rules/helpers | Full Exchange/Graph design |
| **PowerPoint** | Slides, shapes, presentations for deck generation | Design systems / master aesthetics |
| **Access** | Forms/reports automation beside Jet/ACE data | Database design / SQL curriculum |
| **Excel** | Primary LOB host for many orgs | Covered in ch **08** |

Each host has its own VBA reference under Microsoft Learn. Staff fluency means knowing **which OM you are in** and not copying Excel `Range("A1")` idioms into Word.

### 7. Cross-app Automation sketch

From Excel, create or attach Word, push content, save, release (chapter **07**):

```vb
Dim wd As Object
Dim doc As Object
Set wd = CreateObject("Word.Application")
wd.Visible = False
Set doc = wd.Documents.Add
doc.Content.Text = "Report generated from Excel"
' save path must be controlled — ch 11
doc.Close SaveChanges:=False
wd.Quit
Set doc = Nothing
Set wd = Nothing
```

This is a **shape** for review: late binding, visibility choice, cleanup. Production code adds error handling (chapter **05**), path discipline (chapter **11**), and org-approved locations.

### 8. Lab — prefer Range over Selection

```vb
Sub StampFooterNote()
    Dim doc As Document
    Set doc = ThisDocument
    doc.Content.InsertAfter vbCrLf & "Generated by LOB macro"
End Sub
```

**What just happened:** document content mutated without selecting anything in the UI.

## 2. Advanced concepts

### 1. Templates vs documents

Word logic often lives in **templates** (`.dotm`) that produce documents (`.docm` / `.docx`). Auto macros and Document events behave differently depending on where the code lives—chapter **12**. Distributing `.docm` email attachments hits the same macro/MotW controls as Excel (chapter **15**).

### 2. `Document_Open` door

`Document_Open` in `ThisDocument` runs when a document opens **and macros are enabled**. That is a powerful convenience and a defender-visible auto-run surface. Literacy only here; details and review habits in chapter **12**, policy in **15**, safe sample reading in **16**.

### 3. Word auto macros — `AutoNew` / `AutoClose` / `AutoExit` (with `AutoExec`)

Alongside modern `Document_*` events, Word still recognizes classic **auto macros** by reserved names (when macros are enabled and the procedure lives in a reachable project—Normal, active document, or attached template; `AutoExec` has stricter “global/startup” rules):

| Auto macro | When it runs (literacy) |
|------------|-------------------------|
| **`AutoExec`** | Word starts or a qualifying global template loads |
| **`AutoNew`** | A new document is created |
| **`AutoOpen`** | An existing document opens |
| **`AutoClose`** | A document closes |
| **`AutoExit`** | Word exits or a qualifying global template unloads |

Staff habits:

- Prefer **`Document_Open` / `Document_Close` / `Document_New`** in `ThisDocument` for new LOB templates (chapter **12**).
- Still **inventory** `Auto*` names in brownfield and in review—naming conflicts resolve toward the “closest” project (document beats template in common cases).
- Treat every auto-run name as a security-relevant entry point (chapters **15–16**)—this table is recognition, not a recipe to hide behavior.

### 4. Outlook recognition door — `NameSpace` / MAPI / `MailItem`

Outlook VBA is its own object model. For literacy when reading cross-host code (not a mail-spam curriculum):

| Name | What it is |
|------|------------|
| **`NameSpace`** | Root access to Outlook data stores; typically obtained via `GetNamespace("MAPI")` |
| **MAPI** | The messaging subsystem string Outlook VBA uses for the default namespace |
| **`MailItem`** | A mail message item (create/display/send surfaces live here in the OM) |
| **Folders / Explorers** | Navigation and folder contents—deeper product work |

Cross-app Automation that touches mail hits **object-model guard / security prompts** depending on antivirus and policy. Prefer Graph / Power Automate when cloud mail is the real goal (chapter **18**). Do not use this door to design phishing, bulk unsolicited mail, or stealth senders—reviewers treat those as out of scope and hostile.

### 5. Access as a different animal

Access VBA shares language DNA but centers on forms, reports, and data. Treat Access projects as their own LOB stack. Do not assume Excel performance or distribution habits transfer.

### 6. PowerPoint generation

Deck builders loop `Slides` / `Shapes` and set text frames. Keep branding/layout in templates; keep VBA to data fill. Huge shape-by-shape formatting in VBA is unmaintainable—same “don’t fight the product” lesson as Excel Select.

### 7. Early bind host, late bind peer

When Word code talks to Excel (or vice versa), early-bind the host you run inside; late-bind the peer to reduce reference skew (chapter **07**). Document required apps in the workbook/template README.

### 8. Protected view and editable opens

Files from the internet may open in Protected View until edited. Macros and full OM behavior depend on trust state—chapter **15**. Automation that expects immediate write access must account for how the file was opened.

### 9. Content controls — structured regions for LOB templates

Modern Word templates increasingly use **content controls** instead of hunting for placeholder strings with `Find`. A content control is a tagged/titled region (rich text, plain text, date, dropdown, checkbox, …) that authors place in the template and macros fill by contract.

Literacy shape:

```vb
Dim cc As ContentControl
For Each cc In ThisDocument.ContentControls
    If cc.Title = "CustomerName" Or cc.Tag = "CustomerName" Then
        cc.Range.Text = "Contoso Ltd"
    End If
Next cc
```

| Idea | Staff takeaway |
|------|----------------|
| **Title / Tag** | Treat as the API between template authors and VBA—document the contract |
| **`ContentControls` collection** | Enumerate or pick by index; prefer stable Title/Tag over positional luck |
| **`Range` inside the control** | Where text/value lands—still Range-first thinking |
| **vs placeholders** | Survives minor wording edits better than `Find` for `"<<CustomerName>>"` |
| **Events door** | `ContentControlOnEnter` / `OnExit` / before-update events exist on `Document`—thin handlers only (chapter **12**) |

If the template still uses free-text placeholders, document the exact tokens as an API. Prefer content controls for maintained LOB letterhead and forms. Deep control-type catalogs are Word product work; reviewers should demand a sample `.dotm` in the test plan.

### 10. Saving formats and macro reality

| Format | Typical meaning |
|--------|-----------------|
| `.docx` | Document without VBA project |
| `.docm` | Macro-enabled document |
| `.dotm` | Macro-enabled template |
| `.pdf` export | Output door—macros do not live in the PDF |

Export-to-PDF from Word/Excel is a common LOB finish step. The macro that creates the PDF still needed trust to run; the PDF itself is not a VBA host. Keep distribution formats honest in ops docs.

## 3. Applications and use cases

| Domain | Pattern |
|--------|---------|
| **Application** | Word: Range-based insert/replace; Excel peer for tabular source data |
| **Systems** | One host owns the job; peer apps are explicit dependencies with cleanup |
| **Security** | Cross-app ProgIDs reviewed; mail Automation not a stealth C2 toy—policy first (ch **15**) |
| **Operations** | Headless Word/Excel instances monitored for orphans after batch jobs |
| **Software engineering** | Templates hold shared code; documents hold data; events documented (ch **12**) |

Legitimate patterns: invoice letter from Excel row, export range to a Word table, PowerPoint KPI deck from a verified sheet. Illegitimate patterns are out of scope—reviewers use chapters **15–16**.

## Staff-level review checklist

- Word logic uses `Range` / document references more than `Selection`.
- `ThisDocument` vs `ActiveDocument` choice is intentional.
- Cross-app `CreateObject`/`GetObject` follows chapter **07** release rules.
- Peer application prerequisites and bitness are documented.
- Template vs document code location is clear (ch **12**).
- Content controls addressed by documented Title/Tag contracts—not brittle whole-document `Find` for placeholders when a structured template exists.
- Word `AutoExec` / `AutoNew` / `AutoOpen` / `AutoClose` / `AutoExit` inventoried alongside `Document_*` events (ch **12**, **15**).
- Outlook usage limited to named business purpose; `NameSpace`/`MailItem` recognition only—no unsolicited-mail patterns.
- Outlook/PowerPoint/Access usage matches a named business purpose—not copy-paste OM tourism.
- Save paths and filenames are controlled (ch **11**).
- Auto-open handlers are inventoried and justified (ch **12**, **15**).
- No secrets in document variables or Automation payloads.
- Error paths still `Quit`/release external apps (ch **05**, **07**).
