# 10 — Exit, relocation, and decommission

[← Previous](./9_Bandwidth_And_Cross_Connect_Lifecycle.md) · [README](./README.md)

## 1. Concepts

Leaving or shrinking a cage is a project: **assets**, **data**, **circuits**, **badges**, **contracts**.

| Stream | Jobs |
|--------|------|
| Data | Wipe/crypto-erase ([Storage-Physical/10](../Storage-Physical/10_Encryption_And_Key_Custody.md)) |
| Iron | Unrack, pack, ship or destroy |
| Network | Cancel XC/on-ramps ([9](./9_Bandwidth_And_Cross_Connect_Lifecycle.md)) |
| Access | Badges removed |
| Commercial | Exit fees, notice periods ([2](./2_Contract_Capacity.md)) |
| Evidence | Photos empty cabinet; portal inventory zero |

## 2. Advanced concepts

### Failure modes

| Failure | Impact |
|---------|--------|
| Iron left powered | Billing continues |
| Disks leave without erase | Breach |
| XC left live | Surprise dependency break later |
| Badge not revoked | Security gap |
| Notice missed | Another term locked |

### How it connects

Relocation = intake ([8](./8_Dedicated_Metal_Intake.md)) at destination + exit here overlapping. Remote hands for teardown [5](./5_Remote_Hands_Tickets.md).

## 3. Applications and use cases

| Goal | Pattern |
|------|---------|
| Full exit | Parallel checklist streams; single RACI |
| Shrink | Partial unrack + power commit reduce |
| Emergency | Prioritize data wipe + access revoke |
| Audit | Empty-cage photo + zero inventory |

**Staff checklist**

- Notice dates calendared early  
- Wipe standards applied  
- Circuits cancelled knowingly  
- Badges revoked  
- Never assume “we stopped using it” ends billing  

**Good:** checklist exit, wipe proof, clean portal. **Bad:** orphan iron; live XC; billing zombies.
