## 1. Concepts

India is a **peer market** in this curriculum—not the center of gravity, not an afterthought.

| Kind | Examples (illustrative) |
|------|-------------------------|
| Interconnection colo | Equinix Mumbai (MB*), Chennai |
| Regional colo / campuses | CtrlS, Yotta, Nxtra, Sify, STT GDC India, Web Werks/Iron Mountain JV, NTT India, Pi |
| Bare-metal cloud | OVH `ap-south-mum` / YNM-class |
| Tenant cloud | AWS ap-south-1/2, GCP asia-south*, Azure India, Oracle/IBM |

Mumbai and other metros differ—building-level diligence still applies.

## 2. Advanced concepts

### Research notes

- Power and cooling stress in hot seasons—ask density/liquid honestly  
- Interconnect density varies by campus inside Mumbai  
- Cloud regions ≠ automatic colo XC  
- Regional champions often beat global brands on domestic reach

## 3. Applications and use cases

| Goal | Pattern |
|------|---------|
| Domestic apps | CtrlS/Yotta/Nxtra-class shortlist + cloud region |
| Interconnect / multi-cloud | Equinix MB* + on-ramps |
| Bare metal | OVH Mumbai or colo your own iron |
| DR | Two metros (e.g. Mumbai + Chennai/Hyderabad logic) |

**Staff checklist**

- Metro+campus named  
- Cloud region codes correct  
- Seasonal cooling/power asked  
- Hands SLA tested  
- Don’t center the whole handbook on India—or erase it  

**Good:** peer-quality diligence, multi-operator shortlist. **Bad:** Mumbai-as-one; ignore regional champions; stale MB lists.
